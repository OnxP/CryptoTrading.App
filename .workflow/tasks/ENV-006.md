# ENV-006 Clone upstream Kronos into third_party and install its requirements
Objective: Pristine upstream Kronos checkout at a recorded commit, with its requirements installed into the venv without downgrading the CUDA torch.
Current behaviour: No Kronos clone anywhere under C:\Local or the repo. `third_party/` does not exist.
Allowed files: kronos-service/third_party/Kronos/ (git clone; add `kronos-service/third_party/` to .gitignore OR vendor as submodule — pick submodule only if decision 1 keeps everything in this repo), docs/KRONOS_UPSTREAM.md (new: URL, commit SHA, clone date, Python/torch versions), kronos-service/requirements.lock.txt (new, `pip freeze`), .workflow/handoffs/ENV-006.md
Forbidden: editing anything inside third_party/Kronos; `pip install -r requirements.txt` without `--no-deps`-style protection if it would replace the cu130 torch (check `pip install --dry-run` first); installing FastAPI/SQL deps (that is M3).
Acceptance checks:
- `git -C kronos-service\third_party\Kronos rev-parse HEAD` equals the SHA in docs/KRONOS_UPSTREAM.md.
- `git -C kronos-service\third_party\Kronos status --porcelain` is empty.
- After `pip install -r third_party\Kronos\requirements.txt`: `check_cuda.py` from ENV-005 still prints `CUDA: True` and the torch version is unchanged.
- `kronos-service\.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'kronos-service/third_party/Kronos');from model import Kronos, KronosTokenizer;print('import ok')"` prints `import ok`.
Risk: L1
Stop conditions: requirements would change torch → stop and report the conflicting pin; upstream repo URL unreachable → stop.
