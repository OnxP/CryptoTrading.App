# OPT-004 Research request intake: schema, instrument lookup, window and as-of rules
Objective: `ResearchRequest` capturing request id, requester, original question, project, canonical instrument (venue/symbol/currency), evidence links or pasted text, news window, as-of cutoff, optional horizon, requested analyses, delivery preference, parent request id. A deterministic `IntakeValidator` resolves instruments through a fixture lookup and applies window rules.
Current behaviour: none.
Allowed files: options-research/src/options_research/intake/**, options-research/fixtures/instruments.json, options-research/tests/test_intake.py, .workflow/handoffs/OPT-004.md
Forbidden: guessing a ticker; defaulting an as-of to "now" silently; any delivery field defaulting to send.
Acceptance checks:
- "this stock", or a name matching two instruments -> `Clarification` with the candidates, never a request.
- Explicit window 2026-10-01 to 2026-10-07 is preserved exactly (test compares bounds).
- Omitted window -> configured default applied AND listed in `disclosures`; no configured default -> `Clarification`.
- Omitted as-of -> request time, recorded as `as_of_source = "request_time"`; as-of in the future -> rejected.
- Trade horizon not required for a news summary; a time-dependent trade analysis requested without horizon -> `Clarification`.
- Delivery preference defaults to `inline`; email delivery is rejected at intake in M1.
Risk: L3 (as-of semantics)
Stop conditions: any path where an unresolved instrument reaches a specialist.
Context: docs/CLAUDE_SETUP.md "Ad hoc research requests", "Research intake context".
Status: COMPLETE (see .workflow/handoffs)
