# OPT-101 Connector interfaces, RecordingHttpClient, cassette harness, recording script
Objective: One HTTP seam for all external data. `HttpClient` protocol (get(url, params, headers) -> (status, json, received_at)); `RecordingHttpClient` wraps a real client and writes JSON cassettes; `ReplayHttpClient` serves cassettes and raises `NoCassette` on a miss. Cassettes carry request (method, url, sorted params, header names only), response, `received_at`, and `source: "docs"|"live"`. `scripts/record_cassettes.py` records live only when the named token env var is set AND `--record` is passed; it strips secrets from stored headers.
Current behaviour: M1 has no HTTP code; tests block sockets.
Allowed files: options-research/src/options_research/connectors/{__init__,http,cassette}.py, options-research/scripts/record_cassettes.py, options-research/fixtures/cassettes/README.md, options-research/tests/test_cassettes.py, options-research/requirements.txt (add `httpx` only; pin), .workflow/handoffs/OPT-101.md
Forbidden: any network call in tests; storing a token, Authorization value or cookie in a cassette; retries that hide rate limits.
Acceptance checks:
- Replay of a hand-written cassette returns identical status/json/received_at; a request not in the cassette raises `NoCassette` (no fallback to live).
- Recording strips `Authorization` and any header whose name contains key/token; test uses a stub real client (no socket).
- Cassette key is stable under param reordering.
- Suite still passes with sockets blocked.
Risk: L1
Stop conditions: any suggestion to let tests call the network when a token is present.
Context: OPTIONS_M2_PLAN decisions 1-2.
Status: COMPLETE (see .workflow/handoffs)
